MNIST 识别流程、疑问解析及个人改进

这篇笔记整理了我做 MNIST 手写数字识别时的主要流程、对几个常见问题的理解，以及针对本地自造测试集不稳定问题做的预处理改进。

主要流程与代码结构

整体流程可以拆成五步：数据准备与预处理、构建 CNN 模型、训练模型、评估模型，以及单张本地图片预测。训练阶段重点关注损失函数、反向传播和优化器更新；预测阶段则要保证输入图片与训练数据拥有一致的尺寸、灰度分布和标准化方式。

自造本地测试集

官方 MNIST 测试集通常能取得较稳定的准确率，但自己随手画的数字会遇到分布不一致的问题。例如笔画颜色、背景亮度、线宽、数字位置都会影响模型输出。

个人流程疑问

Q：为什么要有 transforms.Normalize((0.1307,), (0.3081,))？

A：这是在用 MNIST 官方统计量做标准化。0.1307 是 MNIST 训练集所有像素的平均值，0.3081 是 MNIST 训练集所有像素的标准差。这样做是为了让训练和推理保持统一分布，使梯度更平稳，并加速收敛。对于其他识图程序，这两个数不一定相同，需要根据实际数据重新统计。

Q：MNIST 官方下载的包为什么打不开？

A：下载得到的是 MNIST 的 Binary 索引格式，并不是标准 PNG 或 JPG 图片，因此不能直接用普通看图软件打开，需要用程序按格式解包读取。

Q：自己造的数据完全测不准怎么办？

A：我的推测是输入分布与训练集差异太大：笔画太细、背景不是黑底、数字不是白字时都可能识别错误。因此可以先做粗糙的黑底白字转换，再根据前景占比对亮区做膨胀。

if ImageStat.Stat(img).mean[0] > 127:
    img = ImageOps.invert(img)

foreground_ratio = sum(px > 0 for px in img.getdata()) / (28 * 28)
if foreground_ratio < 0.08:
    img = img.filter(ImageFilter.MaxFilter(3))
if foreground_ratio < 0.04:
    img = img.filter(ImageFilter.MaxFilter(3))

这段逻辑会在转换成黑底后判断数字笔画占比。若占比小于阈值，就通过 MaxFilter 让亮区膨胀，使细笔画更接近 MNIST 的数据形态。训练 10 个 epochs 后，本地样例的预测置信度基本可以达到 99.5% 以上。

MNIST Recognition Workflow, Questions, and Personal Improvements

This note summarizes my MNIST handwritten-digit recognition workflow, several questions I encountered, and preprocessing improvements for unstable predictions on handmade local test images.

Main Workflow and Code Structure

The workflow can be divided into five stages: data preparation and preprocessing, CNN model construction, model training, model evaluation, and single local-image prediction. The training stage focuses on loss computation, backpropagation, and optimizer updates; the prediction stage must keep image size, grayscale distribution, and normalization consistent with the training data.

Handmade Local Test Set

The official MNIST test set is usually stable, but handmade digits can deviate from the training distribution. Stroke color, background brightness, line width, and digit placement can all affect the model output.

Questions From the Workflow

Q: Why use transforms.Normalize((0.1307,), (0.3081,))?

A: These are the official MNIST training-set statistics. 0.1307 is the mean of all pixels, and 0.3081 is the standard deviation. Normalization keeps training and inference in the same distribution, makes gradients smoother, and speeds up convergence. For other image-recognition tasks, these values should be recomputed from the actual data.

Q: Why can the official MNIST package not be opened directly?

A: MNIST is stored in a binary index format rather than standard PNG or JPG files, so it needs to be decoded programmatically.

Q: What if handmade local data is almost always misclassified?

A: My guess is that the input distribution differs too much from the training set. Thin strokes, bright backgrounds, or non-white digits may cause recognition errors. A practical fix is to convert the input to a black-background, white-stroke style and then thicken foreground pixels when the foreground ratio is too low.

if ImageStat.Stat(img).mean[0] > 127:
    img = ImageOps.invert(img)

foreground_ratio = sum(px > 0 for px in img.getdata()) / (28 * 28)
if foreground_ratio < 0.08:
    img = img.filter(ImageFilter.MaxFilter(3))
if foreground_ratio < 0.04:
    img = img.filter(ImageFilter.MaxFilter(3))

After converting to a black background, this code checks the digit foreground ratio. If the ratio is below the threshold, MaxFilter expands bright regions so thin strokes become closer to the MNIST data distribution. After training for 10 epochs, the confidence on local samples can generally exceed 99.5%.
